# 变更提案: CI 三平台矩阵测试

## 需求背景

npx CLI 工具需要在多个平台和 Node.js 版本上稳定运行。本地测试基线（`npm test`）已在主方案包中实现，但无法覆盖：
- 不同操作系统的差异（路径分隔符、权限模型、环境变量）
- 不同 Node.js 版本的 API 差异（如 `fs.rm` 在 Node 14.0 不可用）

**痛点：**
- 开发者通常只在单一平台开发，难以发现跨平台问题
- Node.js 版本升级可能引入兼容性问题
- 手动跨平台测试成本高、覆盖不全

## 变更内容

1. 创建 GitHub Actions workflow 文件
2. 配置三平台矩阵（ubuntu / macos / windows）
3. 配置 Node.js 多版本矩阵（14 / 16 / 18 / 20）
4. 集成测试报告和状态徽章

## 影响范围

- **模块:** CI/CD
- **文件:**
  - `.github/workflows/test.yml` (新增)
  - `README.md` (更新徽章)
- **API:** 无
- **数据:** 无

## 核心场景

### 需求: 自动化跨平台测试
**模块:** ci

每次 push 和 PR 自动运行测试。

#### 场景: Push 触发
开发者 push 代码到任意分支
- 自动触发 CI workflow
- 在 3 平台 × 4 版本 = 12 个环境中运行测试
- 汇总测试结果

#### 场景: PR 触发
开发者创建或更新 PR
- 自动触发 CI workflow
- PR 页面显示测试状态
- 阻止合并失败的 PR（可选）

### 需求: 测试报告
**模块:** ci

提供清晰的测试结果反馈。

#### 场景: 测试通过
所有矩阵任务通过
- 显示绿色状态徽章
- PR 可以合并

#### 场景: 测试失败
部分矩阵任务失败
- 显示红色状态徽章
- 明确标识失败的平台/版本组合
- 提供失败日志链接

## 风险评估

- **风险:** CI 运行时间过长
- **缓解:** 矩阵任务并行执行，单任务预计 < 2 分钟

- **风险:** Windows 路径问题导致测试失败
- **缓解:** 测试代码已使用 `path.join()` 和 `os.homedir()`
