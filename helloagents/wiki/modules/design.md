# design

## 目的
执行方案设计阶段，构思可行方案并制定详细执行计划，生成方案包。

## 模块概述
- **职责:** 方案构思、详细规划、方案包生成
- **状态:** ✅稳定
- **最后更新:** 2025-12-16

## 规范

### 需求: 方案构思
**模块:** design

根据需求分析结果，构思可行的技术方案。

#### 场景: 单方案场景
需求明确，只有一种合理方案
- 直接进入详细规划
- 无需用户选择

#### 场景: 多方案场景
存在多种可行方案
- 列出方案选项及优缺点
- 等待用户选择
- 推进模式下自动选择推荐方案

### 需求: 详细规划
**模块:** design

生成完整的方案包文件。

#### 场景: 方案包创建
方案确定后
- 创建目录 `plan/YYYYMMDDHHMM_<feature>/`
- 生成 why.md（变更提案）
- 生成 how.md（技术设计）
- 生成 task.md（任务清单）
- 处理同名冲突（使用版本后缀）

## 数据模型

### 方案包结构
| 字段 | 类型 | 说明 |
|------|------|------|
| why.md | file | 变更提案，包含需求背景、变更内容、影响范围 |
| how.md | file | 技术设计，包含技术方案、架构设计、ADR |
| task.md | file | 任务清单，包含可执行的任务列表 |

## 依赖
- core（全局规则）
- templates（文档模板）
- analyze（需求分析结果）
