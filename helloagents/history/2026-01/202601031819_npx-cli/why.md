# 变更提案: npx CLI 自动配置工具

## 需求背景

当前 HelloAGENTS 规则集需要用户手动复制文件到目标目录（`~/.claude/` 或 `~/.codex/`），操作繁琐且容易出错。用户需要：
1. 了解不同平台的配置目录
2. 选择正确的语言版本
3. 手动复制文件
4. 处理与现有配置的冲突

**痛点：**
- 手动操作容易出错
- 新用户不熟悉配置目录位置
- 无法自动处理已存在配置的冲突
- 更新时可能误覆盖用户自定义的规则

## 产品分析

### 目标用户与场景
- **用户群体:** 使用 Claude Code 或 Codex CLI 的开发者
- **使用场景:** 首次安装或更新 HelloAGENTS 规则集
- **核心痛点:** 手动配置繁琐，更新时担心丢失自定义配置

### 价值主张与成功指标
- **价值主张:** 一键安装，安全更新，零配置门槛
- **成功指标:**
  - 用户可通过 `npx helloagents` 完成配置
  - 支持交互式选择平台和语言
  - 文件级冲突处理，保护用户自定义配置
  - 支持非交互式自动化更新（CI/CD 场景）

### 人文关怀
- 提供清晰的交互提示
- 保护用户现有配置（默认生成 `.new` 而非覆盖）
- 支持多语言（中文/英文规则集）
- 失败时提供清晰的恢复指令

## 变更内容

1. 创建 npm 包 `helloagents`（零依赖，纯 Node.js 原生 API）
2. 实现交互式 CLI 工具（原生 readline）
3. 支持 Claude Code 和 Codex 两个平台
4. 支持中文和英文两种语言版本
5. 文件级冲突处理：
   - `CLAUDE.md`/`AGENTS.md`: 默认生成 `.helloagents.new`，不覆盖原文件
   - `skills/helloagents/`: 默认备份后覆盖
   - `skills/` 下其他目录: 不触碰
6. 支持 CLI 参数实现非交互式操作

## 影响范围

- **模块:** 新增 CLI 模块
- **文件:**
  - `package.json` (新增)
  - `bin/cli.js` (新增)
  - `lib/` 目录 (新增)
- **API:** 无
- **数据:** 无

## 核心场景

### 需求: 交互式安装
**模块:** cli

用户通过 npx 运行工具，交互式完成配置。

#### 场景: 首次安装
用户运行 `npx helloagents`，目标目录不存在配置
- 显示欢迎信息
- 提示选择平台（Claude Code / Codex）
- 提示选择语言（中文 / English）
- 复制对应规则集到目标目录
- 显示成功信息

#### 场景: CLAUDE.md/AGENTS.md 已存在
用户运行 `npx helloagents`，顶层配置文件已存在
- 检测到已存在配置
- 询问用户处理方式：
  1. 生成 `.helloagents.new`，手动合并（默认）
  2. 备份后覆盖
  3. 直接覆盖
  4. 跳过此文件
- 按用户选择执行
- 显示操作结果及后续建议（如提示使用 diff 合并）

#### 场景: skills/helloagents/ 已存在
用户运行 `npx helloagents`，skills 目录已存在
- 检测到已存在配置
- 询问用户处理方式：
  1. 备份后覆盖（默认）
  2. 直接覆盖
  3. 跳过此目录
- 按用户选择执行

#### 场景: .helloagents.new 已存在且内容不同
用户多次运行工具，之前生成的 `.new` 文件被手工修改
- 检测到 `.new` 文件已存在且内容与即将写入的不同
- 自动将现有 `.new` 改名为 `.helloagents.new.backup-<timestamp>`
- 写入新的 `.new` 文件
- 输出提示告知用户

### 需求: 非交互式安装
**模块:** cli

高级用户通过 CLI 参数实现自动化安装/更新。

#### 场景: 全自动更新 skills
用户运行 `npx helloagents --platform claude --lang cn --skills-only -y`
- 跳过所有交互
- 仅更新 `skills/helloagents/` 目录
- 不处理 `CLAUDE.md`（输出提示已跳过）
- 使用默认策略（备份后覆盖）

#### 场景: Dry Run 预览
用户运行 `npx helloagents --dry-run`
- 显示将要执行的所有操作
- 每一步显示：源 → 目标、操作类型（写入/备份/生成.new/跳过）
- 汇总统计
- 明确声明"不会做任何写入"

### 需求: 跨平台支持
**模块:** cli

工具需要在 Windows、macOS、Linux 上正常运行。

#### 场景: 路径处理
在不同操作系统上运行
- 使用 `os.homedir()` 获取用户主目录
- 使用 `path.join()` 处理路径
- 正确处理文件权限（Unix）

### 需求: 失败恢复
**模块:** cli

操作失败时提供清晰的恢复指引。

#### 场景: 复制过程中失败
文件复制过程中发生错误（如权限不足）
- 保留已创建的备份
- 输出错误原因
- 输出已创建的备份列表
- 输出跨平台恢复命令模板（PowerShell + Bash）

## 风险评估

- **风险:** 覆盖用户现有配置导致数据丢失
- **缓解:**
  - `CLAUDE.md`/`AGENTS.md` 默认生成 `.new` 不覆盖
  - `skills/helloagents/` 默认备份后覆盖
  - 提供 `--dry-run` 预览

- **风险:** 跨平台兼容性问题
- **缓解:**
  - 使用 Node.js 原生 API
  - 零外部依赖
  - 使用 `os.homedir()` 和 `path.join()`

- **风险:** 半写入导致配置损坏
- **缓解:**
  - 使用"临时文件 → 校验 → rename"近似原子写入
  - 失败时保留备份并输出恢复指令

- **风险:** 供应链攻击
- **缓解:**
  - 零外部依赖
  - 完全离线运行
  - 规则集打包在 npm 包内
